1.  **Discovery:** mDNS (`Open`) or UDP Broadcast (`LanOnly`). DarkBLE if configured.

#### 2. Keepalive/Detection Gap Analysis

*   **CRITICAL GAP:** There is **NO ACTIVE KEEPALIVE** mechanism in `manager.rs` or `health.rs`.
    *   `manager.rs:478-490`: `tick()` only prunes peers not seen for **300 seconds** (5 minutes). This is a garbage collection pass, not a liveness probe.
    *   `health.rs:148-158`: `is_healthy()` checks `age_ms < 30000`, but `last_activity` is **only** updated on explicit message success/failure or connection events. If the socket dies silently (e.g., iOS backgrounding kills BLE without RST), `last_activity` freezes at the last successful send. The connection appears "healthy" for up to 30s, then "unhealthy" but **still present in `connected_peers`**.
    *   `manager.rs:263-275`: `PeerDisconnected` event triggers reconnection queue. **This event is never generated by core logic**; it relies entirely on platform callbacks. If iOS CoreBluetooth fails to fire `didDisconnectPeripheral`, the manager waits forever.
*   **Circuit Breaker Scope:** `circuit_breaker.rs` applies **only to relays**. It has no hooks into direct BLE/WiFi transports. A dead direct connection bypasses all circuit-breaking logic.
*   **Health Monitor Isolation:** `TransportHealthMonitor` tracks stats but has **no write-back path** to `TransportManager`. It can report a connection as unhealthy (`get_unhealthy_connections`), but nothing calls this to trigger failover.

#### 3. Failover Path & Silent Silence Failure Mode

*   **Failover Trigger:** Non-existent for silent failures. `EscalationEngine::deescalate()` exists (`escalation.rs:134`) but is never called automatically. It requires an external caller to know the transport is dead.
*   **Silent Silence State:**
    1.  BLE connects. `handle_event(ConnectionEstablished)` adds peer to `transports[BLE].connected_peers`.
    2.  iOS app backgrounds. OS suspends BLE peripheral. No disconnect event fired.
    3.  Android sends data. `send_to_peer` selects BLE (it's in `connected_peers`).
    4.  Platform layer buffers data or fails silently. No `TransportError` or `PeerDisconnected` event returns to core.
    5.  `peer_last_seen` stops updating.
    6.  Manager considers peer "connected" for 5 minutes.
    7.  After 5 min, `tick()` removes peer from `peer_last_seen` and `peer_transports`. **BUT**: `transports[BLE].connected_peers` is **NOT cleaned up** in `tick()`. The transport state remains corrupted.
    8.  Even after cleanup, no reconnection is triggered because `PeerDisconnected` was never received. Target peer reconnection queue (`reconnection_queue`) is empty.

#### 4. Restart-As-Fix Analysis

Restarting the iOS app fixes the issue because:
1.  **Process Death Forces Socket Close:** TCP/BLE sockets are forcibly closed by the OS, generating FIN/RST that Android receives, triggering `PeerDisconnected`.
2.  **State Reset:** All in-memory `TransportState`, `peer_transports`, and `connected_peers` sets are wiped. Stale entries from silent deaths cannot persist.
3.  **Fresh Discovery:** mDNS/BLE advertising restarts, allowing Android to rediscover the peer immediately.
4.  **Reconnection Queue Reset:** Any exhausted backoff states are cleared.

**The Bug Surface:** The delta between "live node with stale state" and "fresh node" is:
*   Lack of active liveness probing (heartbeat/ping).
*   `tick()` failing to reconcile `transports[].connected_peers` with `peer_last_seen`.
*   Absence of health-monitor-driven synthetic disconnect events.
*   Reconnection queue only populated on explicit `PeerDisconnected`, not on health timeout.

#### 5. Fix Sketch (AUDIT-GATE Required)

All changes below touch `core/src/transport/` and require adversarial review per AGENTS.md rule 8.

| Change | File | Effort | Description |
| :--- | :--- | :--- | :--- |
| **Active Liveness Probe** | `manager.rs` | Medium | Add `ping_interval` (e.g., 10s) to `TransportState`. In `tick()`, send lightweight ping to all connected peers. Track `last_ping_ack`. |
| **Synthetic Disconnect** | `manager.rs` | Low | In `tick()`, if `now - last_ping_ack > ping_timeout` (e.g., 30s), emit synthetic `PeerDisconnected` event internally. Triggers existing reconnection logic. |
| **Tick State Reconciliation** | `manager.rs` | Low | In `tick()`, when pruning stale `peer_last_seen`, also remove peer from `transports[t].connected_peers` for all t. Prevents zombie entries. |
| **Health→Manager Hook** | `manager.rs` + `health.rs` | Medium | Register callback via `health_monitor.register_state_change_callback`. On transition to `Disconnected`/`Failed`, inject synthetic `PeerDisconnected` into manager. |
| **Auto-Deescalation** | `escalation.rs` + `manager.rs` | Medium | Wire synthetic disconnect to `EscalationEngine::deescalate()`. If primary transport dies, immediately switch to fallback before reconnection completes. |
| **Bounded Ping Timeout** | `manager.rs` | Low | Make ping timeout configurable. Default 30s. Ensures bounded detection time for silent deaths. |
| **Reconnect on Health Timeout** | `manager.rs` | Low | When synthetic disconnect fires for a target peer, ensure `reconnection_queue` entry is created even without platform event. |
