## 0. Rules of the road (read before any command)

0.1 Read order: `CLAUDE.md` -> `AGENTS.md` (your capability class + hard rules) -> `docs/rules/FREEBUFF.md` -> this file -> `docs/ORCHESTRATION.md` -> `docs/rules/BUILD_AND_CI.md` -> `docs/rules/SECURITY_PROTOCOL.md` -> `docs/rules/ANDROID.md` (Android cars only).
Precedence: those docs win on HOW (format, reporting, tooling, safety). This plan wins on WHAT and ORDER.

0.2 One car at a time, in the order of sections 5 and 9. State lives outside every repo in `C:/Users/SCM/Documents/GitHub/scm-train-state/` (`STATE_DIR`): `TRAIN_STATE.md`, `TRIAGE.tsv`, `jev/`, `tri/`, `rescue/`. Re-read `TRAIN_STATE.md` before every car and update it after every step. Chat is not state.

0.3 `[OPERATOR GATE]` = stop, print the GATE block (0.6), and wait for the operator to type `GO <id>`. Required before any of:
- push, PR creation, PR merge, tag
- branch or tag deletion, worktree removal
- committing work you did not create
- installing on a device, deploying to AWS
- any live-judge spend above $0.02

The operator may answer one GO for a whole group (for example `GO MT-02` or `GO T-3`). That approves every gate inside that group and nothing outside it.

0.4 Never:
- run two build tools at once. Check first: `tasklist | findstr /I "cargo.exe rustc.exe java.exe gradle"` must print nothing.
- `cargo clean --target` (it wipes all of `target/`)
- `git stash`, `git reset --hard`, `git checkout -- <path>` or `git clean` in a worktree this plan did not create
- `git commit -a` (stage explicit paths only)
- force-push, `gh pr merge --admin`, or bypassing required checks
- edit `core/src/{crypto,transport,routing,privacy}/` without gate 2.4
- use emojis. Use [OK] [FAIL] [WARNING] [INFO].

0.5 Shell hygiene (each of these has bitten this repo):
- Run `git add`, `git commit` and `git push` as separate commands; chained, they hang.
- Never read `$?` after a pipe. Use `set -o pipefail` or no pipe.
- In Git Bash, `git show <rev>:<path>` needs `MSYS_NO_PATHCONV=1`.
- Before any build, `df -h /c` must show >= 15 GB free.
- Cargo parallelism: `-j12`; `-j6` if RAM is contended; `-j4` right after a clean. Keep `CARGO_INCREMENTAL=0`.

0.6 Blocks to print

REPORT, after every car:
```
[CAR] <id> <title> | [OK] DONE / [WARNING] PARTIAL / [FAIL] BLOCKED
[SRC] <branch> @<sha> -> PR #<n> (merged @<sha> | not merged)
[LOC] +<ins>/-<del> in <files> files (vendored, excluded: +<n>)
[GATES] build <cmd> exit <code> | CI <run url> <conclusion> | JEV <score>/100 hard gates <ok|list> | review <link or n/a>
[STATE] TRAIN_STATE.md updated | docs/jev-roadmap.md row <id> updated
[NEXT] <next car> (deps met: yes/no)
```

GATE:
```
[OPERATOR GATE] <id>: <exact command(s) about to run>
[WHY] <one line>
[BLAST RADIUS] <what changes; how to undo>
Reply: GO <id> | SKIP <id> | STOP
```

BLOCKED:
1. Write `STATE_DIR/BLOCKED_<id>.md` with the command, its exit code, the last 40 output lines, what you tried, and the next option.
2. Mark the car BLOCKED in `TRAIN_STATE.md`.
3. Continue with the next car whose dependencies are met.

## Appendix A -- merge-tree triage (Git Bash, git >= 2.38, read-only)

Save it as `STATE_DIR/merge_tree_triage.sh`; run it from `wt-train` after `git fetch --prune origin`. It writes loose objects only: no refs and no worktree changes.

```bash
#!/usr/bin/env bash
set -u
MAIN=origin/main
OUT="${1:-C:/Users/SCM/Documents/GitHub/scm-train-state/TRIAGE.tsv}"
T=$(git rev-parse "$MAIN^{tree}")
printf 'ref\tclass\tland_loc\tconflicts\tdate\tbehind\tahead\n' > "$OUT"
git for-each-ref --format='%(refname:short)' refs/remotes/origin |
  grep -v -e '^origin/HEAD$' -e '^origin/main$' -e '^origin$' |
  while read -r ref; do
    if git merge-base --is-ancestor "$ref" "$MAIN"; then continue; fi
    counts=$(git rev-list --left-right --count "$MAIN...$ref")
    behind=${counts%%[[:space:]]*}; ahead=${counts##*[[:space:]]}
    date=$(git log -1 --format=%cs "$ref")
    out=$(git merge-tree --write-tree --name-only --no-messages "$MAIN" "$ref" 2>/dev/null)
    rc=$?
    tree=$(printf '%s\n' "$out" | head -n1)
    conf=""
    if [ "$rc" -eq 0 ] && [ "$tree" = "$T" ]; then
      class=CONTAINED; loc="0"
    elif [ "$rc" -eq 0 ]; then
      class=CLEAN; loc=$(git diff --shortstat "$MAIN" "$tree")
    elif [ "$rc" -eq 1 ]; then
      class=CONFLICT; loc=$(git diff --shortstat "$MAIN...$ref")
      conf=$(printf '%s\n' "$out" | tail -n +2 | grep -v '^$' | head -5 | paste -sd, -)
    else
      class=ERROR; loc=""
    fi
    printf '%s\t%s\t%s\t%s\t%s\t%s\t%s\n' "$ref" "$class" "$loc" "$conf" "$date" "$behind" "$ahead" >> "$OUT"
  done
```

Also run it on the `rescue/*` branches from P0-2 and on the `pixiegirlchristy/gpt/*` refs. Do this with the ref list swapped; the refs are listed only, never deleted.

## Appendix D -- `scripts/tri3.py` specification

**Inputs**
- `nodes.json`: per node, public_key_hex, identity_id, libp2p PeerId and a clock offset in seconds, plus the run id and commit C.
- `matrix.json`: one entry per message: case, body tag, from, to, expected path (direct | relay | store_forward | any) and message id. Message ids come from CLI send output; Android-originated sends have none.
- `tri3_markers.json`: from MT-09.
- The three logs.

**Events per message**

| Event | Node | What it records |
|---|---|---|
| E1 | sender | outbox enqueue |
| E2 | sender | route decision (path) |
| E3 | sender | transport send attempt (never delivery) |
| E4 | relay | custody accepted |
| E5 | relay | forward to recipient |
| E6 | receiver | received and decrypted |
| E7 | receiver | durable history write |
| E8 | receiver | receipt sent |
| E9 | sender | receipt received, marked delivered |

**Rules** (PASS requires all of them for every matrix message)
- **R1 Completeness:** E1, E3, E6, E7, E8 and E9 are mandatory. E4 and E5 are mandatory exactly when the path is relay or store_forward. For direct paths, the relay log must show no E4 for that id.
- **R2 Order:** after clock correction, with 2 s tolerance: E1 <= E3 <= E6 <= E7 <= E8 <= E9, and E3 <= E4 <= E5 <= E6.
- **R3 Identity:** the sender id in E6 equals the sender's canonical id. The recipient in E1 and E4 equals the receiver's canonical id. Each libp2p PeerId maps to exactly one canonical id across all logs.
- **R4 Uniqueness:** exactly one E7 per message id. Transport duplicates are allowed only when a dedup line is logged.
- **R5 Provenance:** all three logs report commit C.
- **R6 No ACK scoring:** DELIVERED requires E6 + E7 on the receiver and E9 on the sender.
- **R7 Hygiene:** 0 panics. D9-DEGRADE counts are reported. 0 `identity_registration_missing` for matrix recipients.
- **R8 Mesh matrix:** every node pair expected to connect shows a connection-established event in both logs. Disconnects are mirrored within tolerance, or explained by a C7/C8/C10 operator action.

**Outputs**
- `tri_report.md`: one row per message: case, id, path, E1-E9 timestamps per node, verdict, reason.
- `tri_report.json`.
- Exit 0 only when every message PASSes.

**Privacy:** never log or print message bodies, only ids.

**Timestamp formats to parse**
- Rust tracing: RFC3339.
- `docker logs -t`: RFC3339Nano prefix.
- logcat `threadtime,UTC,year`.
