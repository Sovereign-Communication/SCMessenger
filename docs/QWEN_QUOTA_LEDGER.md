## Routing guidance (added 2026-08-02)

### PIN DATED MODEL IDS

The bare aliases `qwen3.7-plus`, `qwen3.7-max`, `qwen3.6-plus`, `qwen3.5-plus`,
`qwen3-max-2026-01-23` and `qwen3.6-max-preview` show **"Not Supported" with no
quota row**, while their dated forms hold full quota. Calls using a bare alias
still SUCCEED, so the spend lands on a row nobody is tracking. Always pass the
dated id, e.g. `qwen3.7-plus-2026-05-26`, not `qwen3.7-plus`.

Same failure shape as the agy shorthand trap: the wrong name does not error,
it silently substitutes.

## THE RULE THAT ACTUALLY PREDICTS 403s (learned 2026-08-02, the hard way)

A model listed as **Enabled** but with a DASH (`-`) instead of a numeric
quota has **no free allowance**. It is enabled for PAID use only. Calls to it
return:

    403 AccessDenied -- "The free quota has been exhausted"

This is what killed two dispatches today: `qwen3.7-plus-2026-05-26` and
`qwen3-coder-30b-a3b-instruct` both show `Enabled` with `-`, and both 403'd
while I believed from an earlier snapshot that they held ~1M.

**Use ONLY models with an explicit numeric Remaining figure.**
Dash-quota models to avoid on the free tier: qwen3.7-plus-2026-05-26,
qwen3.7-max-preview, qwen3.5-flash-2026-02-23, qwen3.5-122b-a10b,
kimi-k2.7-code, qwen3-coder-30b-a3b-instruct, qwen3-coder-480b-a35b-instruct,
qwen-plus, qwen-plus-latest, qwen3-max, qwen3-coder-plus.
